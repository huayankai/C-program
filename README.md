# 日程计划 v1.0（C++ 课设第一版）

一个能**切换日期 → 写下当天的计划 → 打勾把它划掉**的命令行小系统。

- 只用 C++17 标准库，**不需要安装任何第三方库**。
- 数据存在一个文本文件里，关掉程序再打开，计划还在。
- 这份文档是写给"第一次碰 C++ 项目"的人看的：照着做就行，每一步都说清楚为什么。

## 1. 它长什么样

打开之后是这样一屏（`[x]` 那条就是"打勾后被划掉"的效果，真实运行时是灰色 + 删除线）：

```text
============================================================
  日程计划 · 2026-11-07 星期六   [今天]
============================================================

  进度：1/3 [###-------]  33%
------------------------------------------------------------
   [ ] 1. 买牛奶
   [x] 2. 写高数作业  ← 已完成
   [ ] 3. 交实验报告
------------------------------------------------------------
  a 添加   t 打勾/取消   d 删除   j 跳转日期   p 前一天   n 后一天
  h 今天   s 保存        ? 帮助     q 退出
命令>
```

能做的四件事：

| 你想干什么 | 怎么做 |
|---|---|
| 看别的日子 | `p` 前一天 / `n` 后一天 / `j` 跳到任意一天 / `h` 回今天 |
| 写下计划 | `a`，然后打字回车 |
| 完成打勾（划掉） | `t`，再输入那条计划的序号；再打一次就取消 |
| 删掉计划 | `d`，再输入序号 |

## 2. 三分钟跑起来

### 第 1 步：确认有没有编译器

**你这台电脑已经装好了**（`D:\mingw\mingw64\bin\g++.exe`），可以直接跳到第 2 步。
想自己确认一下，打开命令行输入：

```bat
g++ --version
```

能看到版本号（例如 `g++.exe ... 16.2.0`）就没问题。

> 如果提示 `'g++' 不是内部或外部命令`，说明编译器没装、或者装了但没加进 PATH。
> 换一台电脑交作业时，去装一个 **MinGW-w64**（推荐 w64devkit 或 WinLibs 的免安装压缩包），
> 解压后把里面的 `bin` 文件夹路径加到"系统环境变量 → Path"里，关掉命令行重开，再试一次 `g++ --version`。

### 第 2 步：编译（把源码变成 .exe）

双击项目根目录里的 **`build.bat`**。

它会做三件事：检查 g++ 在不在 → 调用 g++ 编译所有 `.cpp` → 生成 `build\ScheduleApp.exe`。

看到这行就成功了：

```text
[成功] 已经生成 build\ScheduleApp.exe
```

（第一次编译要十几秒，正常。）

### 第 3 步：运行

双击 **`run.bat`**。它会先确认 exe 存在（没有就自动编译一次），然后在项目根目录启动程序。

> **为什么要用 run.bat，而不是直接双击 exe？**
> 程序默认把数据存到"当前目录下的 `data\tasks.txt`"。`run.bat` 会先切换到项目根目录（`cd /d "%~dp0"`），
> 所以数据永远存在同一个地方。直接双击 `build\ScheduleApp.exe` 的话，当前目录变成 `build\`，
> 数据就会存到 `build\data\tasks.txt`——数据不会丢，但你会"找不到"它。

## 3. 怎么用（命令速查）

输入**一个字母 + 回车**即可。所有输入都不区分大小写（`A` 和 `a` 一样）。

| 键 | 作用 | 细节 |
|---|---|---|
| `a` | 添加计划 | 会问你"内容>"，打完字回车。**直接回车 = 取消**；内容首尾空格会被去掉 |
| `t` | 打勾 / 取消打勾 | 输入列表里的**序号**（1、2、3…）。已完成会变灰 + 删除线 + "← 已完成" |
| `d` | 删除 | 输入序号。删掉就没了（这一版没有回收站） |
| `j` | 跳到某一天 | 可输入 `2026-09-15`、`2026/9/5`；也可输入 `t`=今天、`n`=明天、`y`=昨天；**直接回车 = 今天** |
| `p` | 前一天 | 跨月、跨年、闰年都算对了 |
| `n` | 后一天 | 同上 |
| `h` | 回到今天 | 迷路了按它 |
| `s` | 立刻保存 | 其实每次改动后都已经自动保存，这个键只是手动确认一下 |
| `?` | 帮助 | 把上面这张表再打印一遍 |
| `q` | 保存并退出 | 关窗口/`Ctrl+Z` 也能退出，退出时同样会保存 |

小提示：

- 列表前面的 `1.`、`2.` 是**"这一天里的第几条"**，换一天会重新从 1 数起，所以它和内部编号不是一回事。
- 输入内容里可以写中文、空格、标点，长度不限（太长的行会自动换行显示）。
- 万一输错了（比如在"要哪条"那里打了 `abc`），程序只会提示一下，不会崩，也不会改坏数据。

## 4. 一次完整的操作示范

假设今天是 2026-11-07，你想给今天加两条计划，再把第二条打勾：

```text
命令> a
给 2026-11-07 添加一条计划（直接回车 = 取消）
内容> 买牛奶
  已添加：[1] 买牛奶

命令> a
内容> 写高数作业
  已添加：[2] 写高数作业

命令> t
要给第几条打勾 / 取消打勾？（直接回车 = 返回）> 2
  已完成，划掉：写高数作业
```

再给明天加一条，然后回今天看看：

```text
命令> n              ← 切到 2026-11-08
命令> a
内容> 复习英语单词
命令> h              ← 回到今天 2026-11-07
```

最后 `q` 退出，再打开一次 `run.bat`，你会发现——东西都还在。

## 5. 我的计划存在哪儿

默认路径：**`data\tasks.txt`**（相对于你启动程序时所在的目录）。
程序启动时屏幕上会打印出来：

```text
  数据文件：data/tasks.txt
```

文件内容长这样，一行一条：

```text
#SCHEDULE v1
1	2026-09-15	0	买牛奶
2	2026-09-15	1	写高数作业
3	2026-09-16	0	复习英语单词
```

| 列 | 含义 |
|---|---|
| 第 1 列 | 编号（系统自动分配；删掉的编号不会再用，避免混淆） |
| 第 2 列 | 日期，格式 `年-月-日` |
| 第 3 列 | 是否已完成：`1` 完成、`0` 未完成 |
| 第 4 列 | 计划内容 |

列与列之间是 **Tab 键**（不是空格）。

日常使用要知道的三件事：

1. **备份 = 复制这个文件**。想恢复就把文件复制回去。
2. **换电脑 = 把这个文件拷到新电脑的同一个位置**。
3. 可以用记事本打开看，但**最好别在程序运行时改它**——程序退出时会整体覆盖这个文件，你的手改会被冲掉。
   真要手改，先关程序、改完、再开程序。

### 为什么不怕"写一半断电"

保存的时候不是直接覆盖 `tasks.txt`，而是先写 `tasks.txt.tmp`，全部写完才把它改名成 `tasks.txt`。
这样任何时刻磁盘上的 `tasks.txt` 要么是**完整的旧数据**、要么是**完整的新数据**，不会出现"半个文件"。

## 7. 代码是怎么跑起来的

一条线，从上到下：

```text
双击 run.bat
  └─ build\ScheduleApp.exe
       └─ src\main.cpp                 只做一件事：把零件拼起来，然后启动
            │
            ├─ util\Console            把控制台设成 UTF-8、打开颜色
            ├─ TextFileRepository      创建"读写 data\tasks.txt"的零件
            ├─ ScheduleService         把上面的零件交给"业务服务"
            │      └─ load()           启动时把文件里的计划读进内存
            │
            └─ AppController           总指挥的循环：
                   ① ConsoleView 画一屏
                   ② 读你输入的命令
                   ③ 是 a 就加、t 就打勾、d 就删……
                   ④ 每次改动后 ScheduleService → TextFileRepository → 写文件
                   ⑤ 回到 ①，直到你输入 q
```

四个层次，依赖方向**只有单向**（`ui` → `service` → `storage`）：

| 层 | 回答什么问题 | 里面有哪些类 |
|---|---|---|
| 界面层 `ui` | 怎么显示、怎么问用户 | `ConsoleView`、`AppController` |
| 业务层 `service` | 什么操作算数、规则是什么 | `ScheduleService` |
| 存储层 `storage` | 数据放在哪、怎么读写 | `ITaskRepository`、`TextFileRepository` |
| 模型层 `model` | 一条计划、一个日期是什么 | `Task`、`Date` |

这样做的好处很实在：**以后换界面（比如做图形界面），`service` 和 `storage` 一行都不用改。**

## 8. 四个可以写进课程报告的设计点

这一节是给"报告里的设计部分"用的，用大白话说清楚就行。

### ① 封装：日期不可能出现"2 月 30 日"

`Date` 的 `year_ / month_ / day_` 都是 `private`，外部拿不到也改不了，只能通过构造函数创建。
构造函数里有校验：月份不在 1~12、或者天数超过当月天数，直接抛异常。

```cpp
Date bad(2023, 2, 29);   // 抛 std::invalid_argument：2023 年 2 月没有 29 日
```

**好处**：只要 Date 能成功创建出来，它就一定是合法日期。后面所有代码都不用再检查"这个日期对不对"。

### ② 运算符重载：日期可以直接比较

```cpp
if (task.date() == today) { ... }      // 不用写成 isSameDay(a, b)
if (a < b) { ... }                     // 不用写成 compare(a, b) < 0
```

`==`、`!=`、`<` 都是我们自己定义的（重载），用起来和 `int` 一样自然，代码可读性明显更好。

### ③ 面向接口：换一种存法，上层代码不用动

`ITaskRepository` 是纯虚接口（只有函数声明，没有实现），`TextFileRepository` 是它的实现。
`ScheduleService` 只认识接口，不认识具体文件：

```cpp
class ScheduleService {
    explicit ScheduleService(ITaskRepository& repository);   // 我只要能 load/save 的东西
    ...
};
```

**好处**：以后想把数据改成 JSON、SQLite，只需要再写一个 `JsonFileRepository`，`ScheduleService` 一个字都不用改。
这就是"面向接口编程"，也是设计原则里说的依赖倒置。

### ④ 原子保存：先写临时文件，再改名

见 [第 5 节](#5-我的计划存在哪儿)。这是一个很实用的小技巧，报告里写出来能体现"考虑过数据安全"。

> 顺带一个初学者常踩的坑，这里已经避开了：如果把很多"多态对象"放进
> `std::vector<Task>`，会发生**对象切片**（slicing），派生类的信息被切掉。
> 第二版加继承时，要改成 `std::vector<std::unique_ptr<Task>>`。第一版暂时不需要。

## 9. 常见问题

**Q1：中文显示成乱码？**
程序启动时会自动把控制台设成 UTF-8，正常双击 `run.bat` 或从 `cmd` 里运行都不会乱码。
如果是在某些 IDE 的"输出窗口"里跑，可能仍会乱码——那是 IDE 自己的编码设置问题，用 `run.bat` 跑就行。

**Q2：`'g++' 不是内部或外部命令`？**
编译器没进 PATH。见[第 1 步](#第-1-步确认有没有编译器)。装好之后**要关掉命令行窗口重新打开**才生效。

**Q3：双击 `run.bat` 一闪就没了？**
说明程序启动就报错了（或者编译没成功）。打开命令行，手动进目录跑一次，就能看到完整报错：

```bat
cd /d D:\git项目\日程计划项目
build\ScheduleApp.exe
```

**Q4：数据好像丢了？**
先看程序启动时打印的"数据文件"路径。多半是你在别的目录运行的，数据写在那边了。
以后统一用 `run.bat` 启动，位置就固定了。

**Q5：打勾了，但没看到"删除线"？**
老版本 Windows 控制台（conhost）不支持删除线这个效果。程序已经同时做了三重标记：
`[x]` + 整行变灰 + 行尾「← 已完成」。在 Windows Terminal 里能看到真正的删除线。

**Q6：列表里的 `1.` 和方括号里的 `[3]` 是一回事吗？**
不是。`1.` 是"这一天里的第几条"（换日期会重排）；`[3]` 是内部编号，只在"已添加"提示里出现，平时不用管。

**Q7：想改一条计划的内容？**
这一版没做编辑功能。先 `d` 删掉，再 `a` 重新加（第二版会加 `e` 编辑）。

**Q8：能把一条计划挪到别的日期吗？**
这一版不行。删掉之后到目标日期重加（第二版会加"移动"）。

**Q9：计划条数多了会不会变慢？**
不会。一天几十条、一个月几百条，对现在的电脑完全不算什么。数据全在内存里，只有保存时才写文件。

## 10. 单元测试

双击 **`build_tests.bat`**，会编译并运行 `tests\test_main.cpp`，最后打印：

```text
用例 16 组，断言 87 条，失败 0 条
全部通过。
```

覆盖了什么：闰年与每月天数、非法日期报错、跨月/跨年/闰日加减、星期几、日期差、
"一条计划 ↔ 一行文本"的互转、格式错误的数据行要被拒绝、存盘后读回、文件不存在时不崩、
加/删/打勾/按日期筛选、重开程序后编号继续往下走（不重复）、字符串工具函数。

**为什么值得写**：日期算法（闰年、跨月）特别容易错，靠手动敲命令测不完。
有了它，你以后改代码，跑一遍就知道有没有弄坏别的东西。这也是课程报告里"测试"一章的现成素材。

## 11. 这一版故意没做的功能，以及下一版怎么加

第一版的目标是**把骨架立稳、把核心玩法做对**，所以下面这些是故意留着的：

| 功能 | 打算怎么做 | 对应评分点 |
|---|---|---|
| 计划分类（学习/生活）、优先级 | 给 `Task` 加两个字段 + 列表里加标签 | 功能复杂度 |
| 每天的重复计划（每周一三五） | `Task` 变抽象基类，派生 `RecurringTask`，覆盖 `occursOn()` | **派生类定义、多态（40 分项）** |
| 有截止日的计划、逾期提醒 | 再派生一个 `DeadlineTask` | 多态 |
| 月历视图（整月网格 + 每天圆点） | `ConsoleView` 加一个 `showMonth()` | 界面完善 |
| 搜索、完成率统计、连续打卡 | `service` 里加 `search()` / `statistics()` | STL 使用 |
| 撤销 / 重做 | 命令模式：`ICommand` + 各种具体命令 | 多态 |
| 图形界面 | 保持 `service` 不变，新增一个 Qt / EasyX 的 View | **图形化界面（40 分项）** |

改动时注意一条原则：**只往上加，不推倒重来**。
因为 `ui → service → storage` 是单向依赖，加功能基本只会动 `service` 和 `model`，界面照旧能跑。

想验证"加功能不弄坏旧功能"，就每次改完双击一次 `build_tests.bat`。

## 附：不是用 g++？还想用别的工具？

- **CMake / CLion / Visual Studio**：项目里已经有 `CMakeLists.txt`，直接用 IDE 打开项目即可。
  ```bat
  cmake -S . -B build -G "MinGW Makefiles"
  cmake --build build
  ```
- **Visual Studio（MSVC）**：`CMakeLists.txt` 里已经加了 `/utf-8` 编译选项，
  否则 MSVC 会把源码里的中文当成 GBK，中文全乱。
- **手动 g++**：编译命令就在 `build.bat` 里，想加参数（比如 `-g` 调试）直接改那个文件就行。

> 补充一句：`build.bat` / `run.bat` / `build_tests.bat` 这三个文件是 **GBK 编码**的。
> 因为中文 Windows 的 cmd 默认按 GBK 读批处理文件，存成 UTF-8 会出现"命令乱码执行失败"。
> 用记事本/VS Code 编辑它们时，保存编码请选择 **ANSI（GBK）**，不要选 UTF-8。
